## 1. 产品概述

### 1.1 定位
面向 10–100 人服务型公司（外包、咨询、代理、营销服务等）的轻量业务管理系统，打通 **获客 → 成交 → 签约 → 收钱** 的完整闭环。单机即可部署，一个二进制文件 + 一个 SQLite 数据库跑全部服务。

### 1.2 解决的核心问题
| 痛点 | 本产品的回答 |
|---|---|
| 客户信息散落在销售的微信/Excel 里，人走数据丢 | 统一客户库 + 负责人归属 + 数据权限 |
| 签了单不知道钱什么时候到、到了没有 | 商单 → 合同 → 回款计划/记录全链路追踪 |
| 合同到期没人记得，续签靠缘分 | 到期/逾期自动提醒 |
| 老板不知道这个月签了多少、回了多少、谁贡献的 | 经营仪表盘 |

### 1.3 目标用户与角色
| 角色 | 说明 | 核心诉求 |
|---|---|---|
| 管理员 admin | 系统负责人 | 全部权限，管账号 |
| 销售 sales | 一线业务人员 | 管自己的客户/商单/合同，看到期提醒 |
| 销售主管 sales_lead | 销售团队负责人 | 看本部门全部数据 |
| 财务 finance | 财务人员 | 管回款、开票，看全部合同 |
| HR | 人事 | 维护员工档案 |

## 2. 名词定义

| 名词 | 定义 |
|---|---|
| 客户 Customer | 服务对象（公司主体），一切业务的源头 |
| 联系人 Contact | 客户侧的具体对接人，一个客户可有多个 |
| 商单 Deal | 一次成交意向："为谁做什么、收多少钱"。赢单后可关联合同 |
| 合同 Contract | 法律履约载体。**商单 ↔ 合同 = N:N**（中间表关联，决策见 §7.1）：一份合同可合并多个商单，一个商单也可拆多份合同，也允许暂不关联商单直接签合同 |
| 回款计划 Payment Plan | 合同约定的应收款节点（如签约 30%、验收 70%） |
| 回款记录 Payment Record | 实际到账流水，关联合同，可核销到计划 |
| 员工 Employee | 系统用户 + 各模块的"负责人"字段来源 |
| 逾期 Overdue | **派生状态**：计划未结清 且 应收日 < 今天。不持久化（决策见 §7.2） |

## 4. 模块详细需求（一期 MVP）

### 4.1 登录与权限
- 邮箱 + 密码登录，密码 bcrypt 加密存储，JWT 会话（有效期 12h）。
- 首次启动初始化 admin 账号，强制要求首次登录改密。
- **admin 可重置成员密码**（一期无邮件服务，重置后线下告知；二期接邮件通知）。
- 权限 = **功能权限**（能不能操作）× **数据范围**（本人 / 本部门 / 全部），矩阵见 §6。

### 4.2 员工档案
- 字段：姓名、邮箱（登录账号）、手机、部门、职位、角色、状态（在职/停用）。
- 停用不删除（历史数据保留负责人快照语义）；停用账号不可登录。
- 部门为单层枚举，由管理员在配置页维护。

### 4.3 客户管理
- 字段：客户编号（自动）、名称、行业、来源、等级、负责人、备注；名称同一公司内唯一（防重）。
- 客户列表：按负责人/行业/来源筛选，关键词搜索，按创建时间排序。
- 联系人：姓名、手机、邮箱、职位、是否首要联系人（每客户至多一个）。
- 客户详情页聚合展示：基本信息 + 联系人 + 商单列表 + 合同列表 + 回款汇总。
- 客户转移：负责人可变更（主管/admin），变更写入审计日志。
- **删除约束**：名下存在商单/合同/回款等下游数据的客户**禁止删除**（类比员工停用），可标记"流失"或等二期客户合并功能；无下游数据的空白客户允许软删除。

### 4.4 商单管理
- 字段：单号（自动）、关联客户、标题、金额、预计签约日期、负责人、状态、赢单概率（按阶段自动带出，可手调）、输单原因、备注。
- **状态机**（对齐 Salesforce Opportunity 标准阶段，9 态裁剪为 6 态）：

  `线索 prospecting → 需求确认 qualifying → 方案报价 proposal → 谈判中 negotiating → 赢单 won / 输单 lost`

  | 阶段 | 默认概率 | 退出标准（达到才允许推进） |
  |---|---|---|
  | 线索 prospecting | 10% | 确认客户存在真实意向 |
  | 需求确认 qualifying | 25% | 摸清需求/预算/决策人（BANT 简版） |
  | 方案报价 proposal | 60% | 报价单或方案已送达客户 |
  | 谈判中 negotiating | 80% | 商务条款进入磋商 |
  | 赢单 won | 100% | 客户确认成交（可关联合同） |
  | 输单 lost | 0% | 必填输单原因 |

- 概率用于仪表盘"加权预测金额"（金额 × 概率），对齐 SF 的预测口径。
- 输单原因枚举（对齐 SF 最佳实践的二分法）：`no_purchase 客户不买了` / `competitor 输给竞品` / `budget 预算不足` / `qualified_out 我方主动放弃` / `other 其他`。
- 仅 `won` 状态可被合同关联；标记 `lost` 必填输单原因。
- **允许回退**：未关闭前（won/lost 之前）可回退到任意前一个阶段（如谈判破裂退回方案报价），回退写审计日志；won/lost 为终态不可逆（lost 不可复活，输错只能新建）。
- **退出标准一期为软校验**：未满足退出标准推进时弹确认提示并记审计（不过度打扰销售）；二期可在系统配置中切换为硬校验。
- **终态锁定**：won/lost 后商单的金额、客户、标题等关键字段只读；变更只能新建商单承接（见 §7.4）。
- 金额输入单位为元，存储为整数分（见 §7.3）。

### 4.5 合同管理
- 字段：合同编号（自动，规则 `HT-YYYY-####`）、**关联商单（0..N 个，N:N 中间表，仅可选 won 状态商单，且必须与合同属同一客户）**、关联客户、标题、金额、签订日期、生效日期、到期日期、状态、负责人、备注。合同金额与商单金额为独立口径（多单合并签约时天然不等额）。
- **状态机**（对齐 Salesforce CLM 默认生命周期，裁剪电子签环节）：

  `草拟 draft → 待签约 pending → 已签约 signed → 履约中 performing → 已完成 completed`

  旁路与回退：
  - `已取消 cancelled`：仅 draft/pending 可取消（签约前作废，SF 的 Canceled）
  - `已终止 terminated`：仅 signed/performing 可终止（签约后提前解除，必填终止原因）
  - `已到期 expired`：signed/performing 到期未续签，由负责人确认后标记（一期人工标记；到期提醒照旧推送）
  - **退回重拟**：pending → draft 允许退回（SF 的 Re-draft 路径，条款谈崩回炉），写审计日志；signed 及以后不可回退

- **终态锁定**：signed 及以后状态，金额、客户、关联商单只读；实际变更（补充协议）走新建合同关联原商单（见 §7.4）。

- 二期在 draft → pending 之间插入 `审批中 approving` 节点（接审批流，SF 的 In Approval Process），状态枚举与流转表现在预留。
- 附件：合同扫描件上传（PDF/JPG/PNG，单个 ≤ 20MB），存储于服务端目录，DB 记录元数据。
- 到期提醒：`signed/performing` 状态且到期日距今 ≤ 30 天，向负责人发站内提醒（每天一次，详见 4.7）。

### 4.6 回款管理
- 回款计划：合同创建后录入，字段：期次、应收日期、应收金额。计划总额不得超过合同金额。
- **计划调整约束**：已被回款记录核销（部分或全部）的计划，禁止修改金额、禁止删除，只能新增调整期次找平；未核销的计划可自由改删。调整写审计日志。
- 回款记录：字段：关联合同、（可选）核销的计划、到账金额、到账日期、方式、备注。
- 计划状态自动推进：`pending → partial → paid`（按计划累计核销额判断）。
- **逾期 = 派生状态**：`status ≠ paid 且 due_date < today`，列表页与仪表盘以红点标识，每日生成站内提醒。
- 合同维度回款汇总：应收总额 / 已收总额 / 未收余额 / 逾期金额。

### 4.7 提醒通知
- 站内通知列表 + 未读角标。类型：合同到期、回款逾期。
- 生成时机：服务端每日定时扫描（启动时 + 每日 09:00）。
- 同一实体同一天同一类型只生成一条（去重）。
- **外发渠道（M3-4）**：站内信之外可开启邮件（SMTP）与企业微信群机器人 webhook，admin 在「通知渠道」页配置，支持按通知类型设白名单、一键测试与外发日志查询；默认全部关闭，外发失败不影响站内信。

### 4.8 经营仪表盘（简版）
- 卡片：本月新签合同额、本月回款额、当前应收余额、逾期金额。
- 列表：近 30 天到期合同 Top10、逾期回款 Top10、本月商单漏斗（各状态数量）。
- 数据范围遵循权限矩阵（销售看本人，主管看部门，admin/财务看全部）。

## 5. 通用需求

- **单号规则**：客户 `KH-YYYY-####`，商单 `SD-YYYY-####`，合同 `HT-YYYY-####`。年度内递增，允许断号（删除不占号）。单号与内部主键完全分离。
- **软删除**：所有业务表 `deleted_at`，删除不进回收站（列表"已删除"过滤即可）。
- **审计日志**：合同、回款、客户负责人变更的增删改，记录操作人/时间/前后值 JSON。一期只写入，二期提供查询页。
- **时间口径**：服务端统一 UTC 存储；日期类字段（到期日、应收日）按自然日，不含时分秒。
- **数据字典**：行业、客户来源、客户等级、回款方式等枚举后端集中定义，前端从接口获取。

## 7. 关键业务决策记录

### 7.1 商单 ↔ 合同 = N:N（评审确认，冻结）
按"最开放的方式"设计：`deal_contracts` 中间表双向关联。覆盖全部真实场景——一单多约（分期签约）、多单一约（合并签约）、先签合同后补商单（0..N 均可）。代价是查询多一次 join、合同表单需多选商单组件，可接受。合同金额与商单金额为独立口径，不做强制勾稽。

### 7.2 逾期不做持久化状态
逾期是"时间 + 未结清"的派生结果。若用定时任务把状态改为 overdue，会引入"状态与实际不一致"的维护负担。查询时派生计算即可。

### 7.3 金额存整数分（INTEGER），全项目禁用浮点
SQLite 的 NUMERIC 亲和在部分场景按 REAL 存储，浮点金额必然丢精度。DB 字段统一 `*_cent INTEGER`，应用层转换展示。

### 7.4 状态流转规则：允许业务回退，禁止终态复活，终态字段锁定
- **业务回退允许**：商单未关闭前可退回前序阶段、合同 pending 可退回 draft（对齐 SF 的 Re-draft），均写审计日志——回退是正常业务动作，堵死会逼用户删除重建丢历史。
- **终态不可逆**：won/lost、completed/cancelled/terminated/expired 不提供"改回上一步"。
- **终态字段锁定**：商单关闭后、合同 signed 后，金额/客户/关联关系只读。真实世界的变更（补充协议、折让）用**新单据**承接并关联原单，历史链路完整可查，审计与回款勾稽永不被追溯性修改破坏。

### 7.5 状态机对齐 Salesforce（评审确认）
- 商单对齐 SF Opportunity 9 标准阶段的裁剪 6 态，并引入"阶段概率 → 加权预测"与"退出标准"两个 SF 核心实践（防止漏斗注水）。
- 合同对齐 SF CLM 生命周期（Draft→Approval→Signature→Activated→Terminated/Expired），裁剪电子签；`approving` 节点一期直通、二期接审批流；`expired` 一期人工标记（不同于 SF 自动过期，避免无人确认时状态偷偷变化）。
- 回款"逾期"仍坚持派生（§7.2），与 SF 的显式 Expired 不同——回款计划数量大、无人值守，派生更不易错。

## 8. 非功能需求

- **部署形态**（评审确认）：Docker 容器 或 裸服务器直接运行，两种交付形态都支持；单租户私有化，非 SaaS。单 Go 二进制 + SQLite 文件 + 附件目录；Docker 部署时 `data/` 目录挂 volume 持久化。提供一键备份脚本（DB + 附件打包）。
- **性能**：单公司数据量级（客户 < 1 万、合同 < 5 千），任意列表页查询 < 300ms。
- **并发**：20 人在线以内；SQLite WAL 模式，服务端单写连接。
- **安全**：密码 bcrypt；接口全部鉴权；附件仅登录用户可下载；默认仅监听内网/127.0.0.1 + 反代。
- **浏览器**：Chrome/Edge 最近两个大版本。
