## 修复：AntD `useForm` 未连接 Form 警告
- 现象：`Warning: Instance created by useForm is not connected to any Form element. Forget to pass form prop?`
- 根因：4 个含 `<Form form={form}>` 的 Modal 都设了 `destroyOnClose`；弹窗关闭时 `<Form>` 被卸载，但 `openEdit` 中的 `form.setFieldsValue(...)` 与新规「新建」按钮的 `form.resetFields()` 在弹窗仍关闭（Form 未挂载）时调用，触发警告。
- 修复：移除 Deals/Employees/Customers/CustomerDetail 中“表单类”Modal 的 `destroyOnClose`（表单已在 onCancel/关闭 时 `form.resetFields()`，无需销毁重建）。流转/输单/转移 3 个纯 Select Modal 无 useForm，保留 destroyOnClose 无影响。
- 教训：AntD 中 `Form.useForm()` + `destroyOnClose` 同用时，绝不可在弹窗关闭态调用 form 方法；要么去掉 destroyOnClose，要么改用 `forceRender` 保持 Form 挂载。
- 已 `pnpm run build` 通过（web/dist 已更新）。

## E2E 验证脚本踩坑（可复用）
- 端到端脚本 `/tmp/e2e_contracts.py`（curl 测登录 200 但脚本报 `KeyError: 'token'`）。
- 根因：本系统 API **所有成功响应都包在 `{"code":0,"data":{...}}` 信封里**（resp.Body 的 `Data` 字段），但脚本误以为 `token`/`id` 在顶层。修复：让 `req()` 在成功 JSON 时返回 `j.get("data", j)`，所有资源访问（c1["id"]、ct1.get("code")、att.get("id")、body["token"]）随之成立。
- 教训：写调用方断言时务必先看 `resp.OK` 的包裹结构，别假定顶层字段。
- 另一坑：本机 `HTTP_PROXY=http://127.0.0.1:6478` 且 `NO_PROXY` 含 `127.0.0.1`，urllib 偶发走代理导致本地请求异常；E2E 启动 server 前务必 `pkill -f <bin>` 清孤儿进程 + 干净 `BSS_DATA` 目录，避免 SQLite 锁/连错实例。
- **E2E `req()` 入参顺序坑（新增记录）**：`req(method, path, body=None, token=None)`。DELETE/GET 带鉴权务必写成 `req("DELETE", path, token=token)`（关键字传 token），若写成 `req("DELETE", path, token)` 会把 token 当 body、实际 `token=None` → 收到 **401**。本次 Sprint 5 E2E 因此误报 401，curl 复现证明后端 DELETE 已核销计划返回正确 422。
